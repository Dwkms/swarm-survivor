## 스폰된 적이 원형으로 멈춰만 있음

스포너는 동작해 `Enemy(Clone)`이 계속 생기는데, 적들이 플레이어를 중심으로 **완전한 원형을
그린 채 한 발짝도 움직이지 않습니다.** 화면에는 아무것도 보이지 않고 Scene 뷰를 축소해야
바깥에 둘러선 적들이 보입니다.

Console에는 오류가 없습니다.

### 원인

**프리팹 원본이 아니라 씬 인스턴스에만 `Enemy` 스크립트를 붙였습니다.**

Unity에서 프리팹 인스턴스(씬에 놓인 것)에 컴포넌트를 추가하면 그 인스턴스만의
**Added Component 오버라이드**로 남습니다. `Overrides → Apply`를 눌러야 프리팹 원본에 들어갑니다.

그래서 이런 상태가 됩니다.

| 대상 | 스크립트 | 결과 |
|---|---|---|
| 씬에 손으로 놓은 Enemy | 있음 | 정상 동작 → **테스트 통과** |
| 프리팹 원본 | 없음 | 클론은 그냥 빨간 사각형 |

**직전 단계의 테스트를 통과했다는 사실이 오히려 판단을 늦춥니다.** 씬 인스턴스로 검증하고
그것을 지운 뒤 스포너를 붙이면, 동작하던 것이 갑자기 안 되는 것처럼 보입니다.

### 판별

Project 창에서 `Assets/Prefabs/Enemy`를 **한 번 클릭**하고 Inspector를 봅니다.
`Enemy (Script)`가 없으면 이 경우입니다.

방증이 하나 더 있습니다. `OnEnable`에 걸어둔 활성 카운터도 돌지 않으므로
**`ActiveEnemyCount`가 계속 0이고 활성 상한에 걸리지 않아 적이 무한정 쌓입니다.**

프리팹이 멀쩡했다면 원인이 다릅니다. 재생 중에 `Enemy(Clone)` 하나를 선택하고
Rigidbody 2D 하단의 **`Info` 폴드아웃**을 펼쳐 Velocity를 봅니다.

| Info의 Velocity | 원인 |
|---|---|
| `(0, 0)` | 코드가 속도를 넣지 못하고 있습니다. 스크립트 체크박스 해제 또는 Move Speed 0 |
| 값이 있는데 안 움직임 | Rigidbody2D **Constraints의 Freeze Position X/Y**가 켜져 있습니다 |

`Freeze Position`은 `Freeze Rotation` 바로 위에 있어 잘못 누르기 쉽습니다.

### 해결

Project 창의 프리팹을 **더블클릭해 Prefab Mode로 들어가서** 컴포넌트를 추가하고, `<` 로 나온 뒤
`Ctrl+S`로 저장합니다.

### 예방

**프리팹 관련 수정은 항상 Prefab Mode(더블클릭)에서 합니다.** 씬 인스턴스를 고치면 오버라이드가
생길 여지가 있고, 그 상태로 테스트를 통과하면 원본이 비어 있다는 사실이 한참 뒤에 드러납니다.

## 적이 화면에 나오지 않는데 오류도 없음

▶ 재생 후 몇 초가 지나도 화면에 적이 하나도 보이지 않습니다. Console에는 아무 메시지도 없습니다.

### 원인

정상인 경우와 결함인 경우가 섞여 있습니다.

**정상** — 적은 반경 14에서 태어나 이동속도 2로 걸어옵니다. 화면 가장자리(가로 10.7 / 세로 6)까지
오는 데 각도에 따라 **1.5~4초**가 걸립니다. 재생 직후에 판단하면 안 됩니다.

**결함** — 가장 흔한 것은 스포너의 `Enemy Prefab` 칸이 비어 있는 경우인데,
초기 코드가 이렇게 되어 있었습니다.

```csharp
if (enemyPrefab == null || playerTransform == null) return;
```

**아무 로그도 남기지 않고 조용히 빠져나갑니다.** 오류도 경고도 없으니 어디를 봐야 할지
단서가 없습니다. 원인 추적이 지연된 실제 이유는 이 한 줄이었습니다.

### 판별

`Start()`에서 전제 조건을 소리 내어 검사하도록 바꿉니다.

```csharp
if (enemyPrefab == null)
{
    Debug.LogError("[Spawner] Enemy Prefab이 비어 있다. Inspector에 프리팹을 넣어라.", this);
}
if (playerTransform == null)
{
    Debug.LogError("[Spawner] Tag가 Player인 오브젝트를 못 찾았다.", this);
}
Debug.Log("[Spawner] 시작됨. 스폰 준비 완료.");
```

- `[Spawner] 시작됨` 로그조차 없음 → 스포너 컴포넌트가 안 붙었거나 오브젝트가 비활성
- `Enemy Prefab이 비어 있다` → Inspector에 프리팹을 드래그
- `Tag가 Player인 오브젝트를 못 찾았다` → 플레이어의 Tag가 `Player`가 아님
- 로그가 다 정상인데도 안 보임 → [스폰된 적이 원형으로 멈춰만 있음](#스폰된-적이-원형으로-멈춰만-있음)

### 해결

빠진 참조를 채웁니다. 근본적으로는 **조용히 실패하는 가드를 두지 않는 것**이 해결입니다.
`return`만 하는 null 체크는 크래시를 막는 대신 원인을 숨깁니다. 시작 시점에 한 번 검사하고
로그를 남기면 진단 시간이 몇 분에서 몇 초로 줄어듭니다.

## 플레이어가 적에게 둘러싸여 갇힘

적이 죽지 않고 쌓이는 상황에서 플레이어가 적 무리에 둘러싸이면 WASD를 눌러도 전혀 움직이지
못합니다.

### 원인

적이 **Dynamic Rigidbody2D + 일반 Collider**, 즉 물리적으로 밀리지 않는 벽이었습니다.
적끼리는 충돌하지 않도록 꺼놨으므로 같은 자리에 무한히 겹쳐 쌓이고, 결과적으로
**아무리 밀어도 뚫리지 않는 두꺼운 벽**이 됩니다.

### 검토했다가 버린 해법

"피격 무적 0.5초 동안 적을 통과할 수 있게 한다"는 안이 있었지만 **채택하지 않았습니다.**
무적이 끝나는 순간 다시 갇히기 때문입니다. 벽이 스무 겹이면 0.5초로는 빠져나올 수 없습니다.
증상을 잠시 가릴 뿐 원인을 없애지 못합니다.

### 해결

적 `Box Collider 2D`의 **`Is Trigger`를 켭니다.** Trigger는 겹침을 알리기만 하고 물리적 반발을
만들지 않으므로, 적이 플레이어 위를 그대로 지나갑니다. 수백 마리가 둘러싸도 갇히지 않습니다.

프리팹을 더블클릭해 Prefab Mode에서 변경하고 `Ctrl+S`로 저장합니다.

### 부수 효과

물리 충돌은 **감지**(broadphase + narrowphase)와 **해결**(solver, 밀어내는 힘 계산)의 두 단계인데
Trigger는 감지만 하고 해결을 건너뜁니다. 적 수백 마리가 플레이어 한 명에게 몰려드는 상황에서
solver가 접촉점을 전부 푸는 비용이 사라지므로 **성능 측정 조건도 함께 개선됩니다.**

트레이드오프로 적들이 한 지점에 완전히 겹쳐 보입니다. 버그가 아니라 선택한 대가입니다.

### 주의

**Trigger도 Layer Collision Matrix를 따릅니다.** 매트릭스에서 꺼진 조합은 Trigger 콜백 자체가
오지 않습니다. `Projectile ↔ Enemy`와 `Player ↔ Enemy`는 켜져 있어야 합니다.

## 같은 마릿수인데 성능 수치가 크게 다름

적 900마리에서 어떤 때는 541fps(1.85ms), 어떤 때는 최소 40fps(25ms)가 나옵니다.
**13배 차이**인데 마릿수는 같습니다.

### 원인

측정할 때마다 **조건이 두 가지 이상 달랐습니다.**

**첫 번째 오염 — 스폰 중에 측정했습니다.**
마릿수를 올리려면 `F1`을 계속 눌러야 하는데, 그 사이에 읽은 값은 마릿수의 비용이 아니라
**한 프레임에 100개를 생성하는 스파이크**입니다. 이 때문에 "950~1000마리에서 60fps가 깨진다"는
결론을 냈다가 폐기했습니다. 스폰을 멈추고 재니 900마리에서도 541fps였습니다.

**두 번째 오염 — 플레이어 이동 여부가 달랐습니다.**

| 조건 | 결과 |
|---|---|
| 900마리 · 플레이어 정지 | 541fps / 1.85ms |
| 900마리 · 플레이어 이동 | 최소 40fps / 25ms |

플레이어가 멈추면 적들이 목표 지점에 도달하고, `(target - position).normalized`가
길이가 극히 작은 벡터에 대해 `Vector2.zero`를 반환하면서 속도가 0이 됩니다.
그러면 물리 엔진이 **900개를 전부 재웁니다(sleep).** 잠든 바디는 시뮬레이션에서 사실상
제외되므로 비용이 사라집니다.

**541fps는 성능이 아니라 적들이 잠들어 있어서 나온 숫자입니다.**

### 판별

정지 상태에서 `Enemy(Clone)` 하나를 선택하고 Rigidbody 2D의 `Info`에서 Velocity를 확인합니다.
`(0, 0)`이면 수면 상태입니다. WASD를 누르면 값이 살아납니다.

스폰 스파이크와 존재 부하를 구분하려면 **`F1`을 누른 뒤 손을 떼고 10초간 관찰**합니다.
누른 순간에만 튀고 이후가 매끄러우면 생성 비용, 계속 버벅이면 존재·이동 비용입니다.

### 해결

측정 규칙을 고정했습니다.

- **한 번에 변수를 하나만 바꿉니다.** 스폰하면서 측정하지 않습니다.
- **모든 측정치에 "플레이어 이동 여부"를 함께 기록합니다.**
  실제 게임에서 플레이어는 항상 움직이므로 **유효한 조건은 "이동 중"** 입니다.
  정지 상태 수치는 폐기했습니다.
- 지표를 평균 FPS가 아니라 **프레임 시간(ms) · GC Alloc · 최악 프레임**으로 바꿨습니다.
  FPS는 프레임 시간의 역수라 비선형이고(570→285와 60→30은 같은 "절반"이지만 실제 증가분이
  1.75ms와 16.7ms로 다릅니다), 평균은 스파이크를 감춥니다.
- 측정 위치(에디터/빌드)와 **어느 PC인지**를 함께 적습니다. 두 PC를 오가며 작업하므로
  데스크탑의 전(前) 수치와 노트북의 후(後) 수치를 비교하면 그 비교는 무효입니다.

기록은 [PERF_LOG.md](./PERF_LOG.md)에 있습니다.

## 총알 한 발이 여러 마리를 죽임

적이 밀집한 곳에서 총알 하나가 두세 마리를 동시에 없앱니다. 관통 무기가 아닌데도 그렇습니다.

### 원인

**`Destroy`는 즉시 실행이 아니라 해당 프레임의 끝에 처리됩니다.**

총알이 첫 적을 맞고 `Destroy(gameObject)`를 불러도 오브젝트는 그 프레임 동안 살아 있습니다.
그 사이에 다른 적과 겹치면 `OnTriggerEnter2D`가 다시 호출됩니다.

적이 한 지점에 겹쳐 쌓이는 구조(적 Collider가 Trigger라 서로 통과)라 특히 잘 재현됩니다.

### 해결

총알에 적중 여부 플래그를 두고 첫 호출 이후를 무시합니다.

```csharp
private bool hasHit;

private void OnTriggerEnter2D(Collider2D other)
{
    if (hasHit) return;

    Enemy enemy = other.GetComponent<Enemy>();
    if (enemy == null) return;

    hasHit = true;
    enemy.TakeDamage(damage);
    Destroy(gameObject);
}
```

적 쪽에도 같은 이유로 `isDead` 플래그가 필요합니다. 같은 프레임에 두 발을 맞으면 `Die()`가
두 번 호출될 수 있습니다.

## 플레이어가 멈춰 있으면 접촉 피해를 받지 않음

적에게 둘러싸여 있는데 가만히 서 있으면 체력이 줄지 않습니다. 움직이면 정상적으로 피해를 받습니다.

### 원인

접촉 피해를 `OnTriggerStay2D`로 받는데, **물리 엔진이 정지한 Rigidbody를 재우면
`OnTriggerStay2D`가 호출되지 않습니다.**

프레임이나 입력이 아니라 물리 엔진의 최적화 동작이 원인이라, 재현 조건을 좁히기 전까지는
원인을 찾기 어렵습니다.

### 해결

플레이어 Rigidbody 2D의 **`Sleeping Mode`를 `Never Sleep`** 으로 설정합니다.

같은 수면 동작이 성능 측정에서는 전혀 다른 문제를 만듭니다.
[같은 마릿수인데 성능 수치가 크게 다름](#같은-마릿수인데-성능-수치가-크게-다름)을 함께 보세요.

## 플레이어가 미세하게 떨림

카메라가 플레이어를 따라갈 때 플레이어가 미세하게 진동하는 것처럼 보입니다.

### 원인

카메라 코드 문제가 아니라 **Rigidbody2D의 `Interpolate`가 꺼져 있는 것**입니다.
물리는 50Hz, 렌더는 60Hz 이상으로 돌기 때문에 두 주기가 어긋나면 떨림으로 보입니다.

### 해결

물리로 움직이는 오브젝트의 Rigidbody 2D에서 `Interpolate = Interpolate`로 설정합니다.

카메라 쪽에서 보정하려 들면 원인은 그대로 둔 채 증상만 다른 형태로 옮깁니다.
`LateUpdate`에서 따라가게 하는 것과는 별개 문제입니다.

## 화면이 검게 나옴

▶ 재생하면 Game 뷰가 완전히 검습니다. Scene 뷰에는 오브젝트가 정상적으로 보입니다.

### 원인

**카메라의 z가 0이 되었습니다.** 2D 카메라는 z = -10이어야 장면을 바라봅니다.
z가 0이면 카메라가 오브젝트와 같은 평면에 있어 아무것도 담기지 않습니다.

`CameraFollow`에서 `transform.position`에 목표 위치를 **통째로 대입**하면 z까지 덮어써서
이 상태가 됩니다.

### 해결

`Awake`에서 초기 z를 캐싱해두고, 위치를 갱신할 때 x·y만 바꾸고 z는 캐싱한 값을 유지합니다.

## 다른 PC에서 컴포넌트가 비어 있음

한쪽 PC에서 붙인 컴포넌트가 다른 PC에서 열면 사라져 있거나 Inspector 참조가 비어 있습니다.

### 원인

**씬 저장(`Ctrl+S`)을 빠뜨렸습니다.**

GameObject 추가와 Inspector의 컴포넌트 설정은 `.unity` 파일에만 기록됩니다. 스크립트 파일만
커밋되고 씬이 저장되지 않으면, 코드는 최신인데 그 코드를 붙일 오브젝트가 없는 상태가 됩니다.

프리팹 수정은 `.prefab`에 저장되므로 씬과 별개입니다. 둘 다 확인해야 합니다.

### 해결

작업 후 반드시 Unity에서 `Ctrl+S`를 누른 뒤 커밋합니다.

```bash
git status      # .unity / .prefab 변경이 잡히는지 눈으로 확인
git add .
git commit -m "..."
git push
```

`.meta` 파일은 **반드시 함께 커밋합니다.** Unity가 에셋 연결 정보를 여기에 저장하므로,
빠지면 다른 PC에서 참조가 전부 끊깁니다.

### 예방

PC를 바꿀 때는 **작업 시작 전에 반드시 `git pull`** 합니다. 씬 파일(`.unity`)은 충돌이 나면
수동 병합이 사실상 불가능합니다.

## 다른 PC에서 Inspector 참조가 비어 있음 (UnassignedReferenceException)

> 2026-09-01 노트북에서 확인.

`git pull` 후 다른 PC에서 실행하면 컴포넌트는 붙어 있는데 **Inspector의 참조 칸만 비어 있습니다.**

```
UnassignedReferenceException: The variable projectilePrefab of BulletWeapon has not been
assigned. You probably need to assign the projectilePrefab variable of the BulletWeapon
script in the inspector. Parameter name: data
```

### 증상이 여러 갈래로 보입니다

한 가지 원인인데 겉으로는 서로 다른 문제처럼 보입니다. 이번에 실제로 겪은 조합입니다.

| 겉으로 보이는 증상 | 실제 원인 |
|---|---|
| 플레이어가 총을 쏘지 않음 | `BulletWeapon`의 Projectile Prefab이 `None` → `Instantiate(null)` 예외 |
| 적에게 닿으면 HP가 깎이지 않고 **플레이어가 사라짐** | `PlayerStats`의 Max Health가 `0` → 첫 피격에 `Die()` → `SetActive(false)` |
| 적 스폰은 정상 | `EnemySpawner`의 참조는 살아 있었음 |

**일부 참조만 끊기므로 "어떤 기능은 되고 어떤 기능은 안 되는" 상태**가 되어, 각각을 다른 버그로
쫓게 되기 쉽습니다. 하나의 원인으로 묶어서 봐야 합니다.

### 원인

Unity는 에셋을 **파일 이름이 아니라 `.meta` 안의 GUID로 참조합니다.** 다음 중 하나면 참조가 끊깁니다.

- `.meta` 파일이 커밋에서 빠져 다른 PC에서 새 GUID가 생성된 경우
- 프리팹 파일 자체가 커밋되지 않은 경우
- 참조를 지정한 뒤 씬을 저장(`Ctrl+S`)하지 않고 커밋한 경우

### 판별

```bash
git ls-files Assets/Prefabs
```

`.prefab`과 `.prefab.meta`가 **쌍으로** 있어야 합니다. 한쪽만 있으면 그것이 원인입니다.

```bash
git check-ignore -v Assets/Prefabs/Projectile.prefab.meta
```

무언가 출력되면 `.gitignore`가 그 파일을 막고 있습니다.

Console의 예외 메시지는 **어느 변수가 비었는지 이름까지 알려줍니다.** 그 컴포넌트를 Inspector에서
먼저 보면 됩니다.

### 해결

Project 창의 프리팹을 Inspector의 빈 칸에 다시 드래그하고, 다른 값도 함께 확인한 뒤
`Ctrl+S` → 커밋 → push 합니다.

**프리팹을 새로 만들지 마세요.** GUID가 또 갈려 같은 문제가 반복됩니다. 파일 자체가 없다면
원래 PC에서 push하는 것이 맞습니다.

`.meta`가 빠져 있었다면 `.gitignore`에서 제외 규칙을 없애고 함께 커밋합니다.

### 예방 (참조 유실)

PC를 옮긴 뒤에는 ▶ 재생 전에 **Console을 Clear하고**, 아래를 먼저 확인합니다.

| 확인 대상 | 정상 값 |
|---|---|
| Player의 Tag / Layer | `Player` / `Player` |
| Player · Rigidbody 2D · Sleeping Mode | `Never Sleep` |
| Player · Bullet Weapon · Projectile Prefab | 채워짐 |
| Player · Player Stats · Max Health | `100` |
| EnemySpawner · Enemy Prefab | 채워짐 |
| Project Settings · Physics 2D 매트릭스 | `Enemy ↔ Enemy` 해제 |

## 에디터에서 잰 성능이 실제 게임 성능과 다름

> 2026-09-02 확인.

에디터 Play 모드에서 잰 프레임 시간이 실제 게임의 부하와 맞지 않습니다. 마릿수를 늘려도
예상만큼 안 오르거나, 반대로 아무것도 안 했는데 크게 튑니다.

### 원인

**프레임 시간의 대부분을 에디터가 쓰고 있습니다.**

Profiler(`Window → Analysis → Profiler`)에서 평범한 프레임 하나를 열어본 내역입니다.

| 항목 | Total | Time ms |
|---|---|---|
| **EditorLoop** | **86.4%** | **10.33ms** |
| PlayerLoop | 11.1% | **1.32ms** |

Scene 뷰 렌더링, Inspector·Hierarchy 갱신, Profiler 창 그리기가 전부 `EditorLoop`에 들어갑니다.
`Time.unscaledDeltaTime`은 **에디터 프레임 전체**를 재므로, 스크립트로 잰 값은 처음부터
`게임 비용 + 에디터 비용`입니다.

### 판별

Profiler를 **Hierarchy** 모드로 두고(왼쪽 `Timeline ▾` 드롭다운에서 변경) `Total` 열로
정렬합니다. `EditorLoop`와 `PlayerLoop`의 비중을 비교합니다.

`Deep Profile`은 켜지 마세요. 모든 함수 호출을 기록하느라 수치가 몇 배로 왜곡됩니다.

### 해결

**기준선은 빌드에서 잽니다.**

1. `Edit → Project Settings → Quality` → `V Sync Count`를 **`Don't Sync`**
   (켜져 있으면 주사율에 묶여 여유가 얼마나 남았는지 알 수 없습니다)
2. `File → Build Profiles` → Windows → `Add Open Scenes` → **Build**
3. **`Development Build`는 체크하지 않습니다.** 프로파일러가 붙으면서 오버헤드가 생깁니다

`PerfMonitor`는 `OnGUI`로 그리므로 빌드에서도 그대로 표시되고 `F1`·`F3`·`F4`도 작동합니다.

### 참고

에디터 측정이 완전히 무의미한 것은 아닙니다. **같은 조건끼리의 상대 비교**에는 쓸 수 있습니다.
다만 "60fps 기준선을 넘는가" 같은 절대 판정에는 쓸 수 없습니다.

## 적을 늘렸는데 평균 프레임 시간이 낮아짐

> 2026-09-02 확인.

마릿수별 곡선을 그리는데 순서가 뒤집혔습니다.

```
200마리  1.98ms
400마리  2.19ms
600마리  0.82ms   ← 더 많은데 더 빠름
900마리  6.85ms
```

### 원인

**화면에 표시되던 값이 직전 0.5초 창의 평균이었습니다.**

`PerfMonitor`가 0.5초마다 문자열을 새로 만들면서, 그 직전 0.5초 동안의 평균만 보여주고
있었습니다. 이 부하는 평균이 아니라 **주기적인 스파이크**로 나타나기 때문에,
스파이크 직전에 읽으면 낮게, 직후에 읽으면 높게 나옵니다.

즉 **측정 대상이 아니라 측정 도구가 문제였습니다.**

### 판별

같은 마릿수에서 화면 값을 몇 초간 지켜봅니다. 값이 크게 오르내리면 그 값은 순간값입니다.

`worst`(리셋 이후 누적 최악 프레임)는 시점에 영향받지 않으므로, `worst`만 단조증가한다면
이 경우입니다. 실제로 `worst`는 5.05 → 10.12 → 25.83 → 63.37로 깨끗하게 증가했습니다.

### 해결

**리셋 이후 모든 프레임을 누적하는 평균(`AVG`)을 추가했습니다.** `worst`와 같은 기준(F4 리셋)으로
맞춰져 두 값을 함께 읽을 수 있습니다. 0.5초 창 값은 `now`로 남겨 참고용으로만 씁니다.

기록에는 **`AVG`와 `worst`만** 사용합니다.

### 예방

**측정 도구를 만들었으면 도구부터 검증합니다.** 알고 있는 방향의 변화(마릿수 증가)를 줬을 때
지표가 그 방향으로 움직이는지 먼저 확인하고, 어긋나면 대상이 아니라 도구를 의심합니다.

## 프리팹을 만들었는데 씬에 원본이 남아 게임 시작부터 아이템이 놓여 있음

> 2026-09-03 확인.

게임을 시작하자마자 아무도 죽이지 않았는데 경험치가 들어옵니다. 재생을 멈춰도 해당
오브젝트가 씬에 그대로 보입니다.

### 원인

**프리팹으로 만든 뒤 Hierarchy의 원본을 지우지 않았습니다.**

씬에 있는 오브젝트는 `.unity` 파일에 저장되므로 게임 시작 시점에 이미 배치되어 있습니다.
`Instantiate`로 생기는 것은 이름이 `XXX(Clone)`이지만, 씬에 남은 원본은 `(Clone)`이
붙지 않습니다.

### 판별

**재생을 멈춘 상태에서 Hierarchy를 봅니다.** 클론은 재생이 끝나면 전부 사라지므로,
멈춘 뒤에도 남아 있으면 그것은 씬에 저장된 원본입니다.

Hierarchy 상단 검색창에 오브젝트 이름을 넣으면 찾기 쉽습니다.

### 해결

Hierarchy에서 삭제하고 `Ctrl+S`로 씬을 저장합니다.

### 예방

프리팹 제작은 **만들기 → `Assets/Prefabs`로 드래그 → 씬의 원본 삭제 → `Ctrl+S`** 를
한 묶음으로 처리합니다. 마지막 두 단계를 빠뜨리기 쉽습니다.

## 같은 스크립트가 두 번 붙어 동작이 두 배가 됨

> 2026-09-03 확인.

스포너가 예상보다 많이 스폰하거나, 같은 처리가 두 번씩 일어납니다.

### 원인

**한 오브젝트에 같은 스크립트를 두 번 Add Component 했습니다.**

Unity는 같은 MonoBehaviour를 중복으로 붙이는 것을 막지 않습니다.
`Update`가 두 번 돌고, 시간 누적도 두 벌이 따로 돌아갑니다.

### 판별

해당 오브젝트를 선택하고 **Inspector를 아래까지 스크롤합니다.** 같은 이름의 컴포넌트가
두 번 나타나는지 봅니다. 컴포넌트가 많으면 위쪽만 보고 지나치기 쉽습니다.

### 해결

중복된 쪽에서 컴포넌트 우측 점 세 개 → `Remove Component` → `Ctrl+S`.

### 예방

`Add Component` 전에 Inspector에서 이미 붙어 있는지 확인합니다.
한 오브젝트에 하나만 있어야 하는 컴포넌트라면 `[DisallowMultipleComponent]` 특성을
클래스에 붙여 Unity가 막게 할 수도 있습니다.
